# Examples own application configuration and reference external infrastructure

Each product project owns new, uniquely named application configuration and references externally provisioned workspaces, identities, target applications, and connected infrastructure. The expanded Gateway project also owns its upstream integrations and explicit workspace bindings, avoiding adoption of shared connections while teaching their dependency graph. Cleanup removes only owned objects; optional organization guardrails require deliberate enablement because organization-scoped policies can affect other workspaces, while tenant plugin settings and shared Supply Chain instances/rules remain external.
